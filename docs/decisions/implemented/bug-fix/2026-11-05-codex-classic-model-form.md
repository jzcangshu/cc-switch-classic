# Agent Note: Codex 经典表单恢复独立默认模型和高级模型映射

Status: implemented（已实施）

## Problem（问题）

当前普通表单把模型列表放在连接信息下，并在列表非空时隐藏独立默认模型输入。旧版用户容易将其理解为必填配置；自动审批模型的无列表说明又强化了这一印象。项目以 3.20.4 版为视觉参照，该版本将独立默认模型放在常用区域，将模型映射放在高级选项。

## Decision（决定）

只恢复普通直连、路由表单的操作布局：默认模型独立显示，模型映射与依赖模型目录的自动审批设置放回高级选项。空映射的普通原生供应商保持折叠；已有映射自动展开，折叠不会清空数据。聚合布局继续直接显示模型列表，因为它用于发布聚合模型。

不增加模型映射开关、持久化字段或数据迁移。沿用当前版本的模型列表状态、默认行联动、元数据补全、预设内容、编辑投影与保存规则。新增的独立输入调用现有默认模型修改接口；获取入口在高级区折叠时放在默认模型旁，展开时使用映射区已有的获取入口。只是调整界面位置和说明，不回滚新版后端能力。

已有模型列表按当前版本规则展示默认行在前，但仅打开、折叠或保存不会改变保存顺序。保留官方模型条目约束、隐藏参数、自动审批选择、子代理设置、上游协议和上下文配置。此前的[客户端提醒优化](2026-11-05-codex-unverified-reminders.md)独立保留。

## Alternatives considered（考虑过的方案）

1. 新增“启用模型映射”开关可以让用途明显，但不是参照版本的操作，会新增开关和列表状态间的契约，并使已有用户面临新的保存语义。按用户要求不采用。
2. 整文件回滚到第三版可以直接还原外观，但会丢失托管账号、聚合、自动审批和模型元数据处理等后来能力，不采用。
3. 只加一行“可留空”说明成本最小，但仍把模型列表放在基础连接区域，不能恢复旧版操作路径。

## Consequences（收益与代价）

普通用户可以只填写连接与默认模型，高级能力仍通过原有入口访问。已有映射的用户升级后能够直接看到配置，并可继续编辑。默认模型与映射默认行在普通布局里都可见，保留现有联动以免改变编辑行为。

## Testing（验证）

完整表单回归检查已有映射折叠后保存、隐藏元数据和自动审批选择保留、无映射配置不隐式生成目录，以及只改默认模型时保存顺序和上下文设置不变。聚合、托管账号、预设切换、模型获取和客户端提醒一起回归。浏览器验收通过已连接的扩展实例，使用真实组件和仓库外的合成数据预览；没有操作真实账号或客户端配置。

本轮基线为 62d23ade（提交标识），审查对象为该基线上的本任务未提交改动。13 个相关测试文件共 175 项通过，类型检查、改动文件格式检查、前端生产构建、文档检查和差异空白检查通过。浏览器实际检查普通空映射、已有映射、聚合列表、提醒静音及重新加载后的保持；简体中文、繁体中文、英文和日文正常显示，900 像素宽的表单没有横向溢出。深浅主题沿用现有组件样式。截图与合成预览均留在仓库外。
