# Agent Note: Codex 未确认客户端提醒允许本机静音

Status: implemented（已实施）

## Problem（问题）

当前客户端探测在 Windows（微软桌面系统）上只能确定托管守护进程的启动时间。对于桌面版和编辑器插件，只比较当前模型目录、文件登录身份与上次确认的指纹。目录或身份变化不代表这些客户端正在运行，更不能确认重启后仍然过期，持续的黄色提示容易造成干扰。

前端还会在应用、模式或供应商变化时清空关闭记录，即使后端报告的目录和身份版本没有改变。模型列表编辑区没有明确说明留空的意义，容易让人误以为所有第三方供应商都必须维护自定义目录。

## Decision（决定）

- 只有无法确认的桌面版、插件提醒使用普通信息样式，并提供“不再提示此类推测”按钮。偏好保存在本机浏览器存储中，不同步账号或供应商数据；存储不可用时仅对当前挂载有效。
- 静音仅过滤无法确认的部分。已探测到的旧守护进程以及可探测平台上的旧桌面进程继续显示警告，重启仍需原有确认。混合状态中优先显示已探测进程的标题。
- 关闭按钮继续确认当前目录和身份。前端按后端状态版本保留关闭记录，不因无关的模式或供应商变化重置；新目录或身份仍重新提醒。
- 普通供应商高级选项中的模型映射说明可以留空，默认使用客户端模型列表。聚合模式说明独立保留，因为聚合模型必须发布目录。没有新增目录写入规则。

## Alternatives considered（考虑过的方案）

1. 完全删除提醒可以消除干扰，但会掩盖已确定仍持有旧目录的进程，因此保留已探测状态。
2. 对所有目录变化继续使用强警告可以减少漏报，但无法区分客户端是否存在，关闭后仍会因常规切换反复出现。
3. 增加 Windows（微软桌面系统）进程命令行探测可以提高准确度，但涉及权限、启动时间与命令行归属判断，不属于本次小范围交互修复。
4. 将静音写入跨设备设置便于集中管理，但提醒来自本机进程能力，沿用本机界面偏好更符合其作用范围。

## Consequences（收益与代价）

用户可以主动停止推测提醒，同时保留明确的进程异常反馈。本机存储重置后会恢复默认提醒；当前没有单独的设置项用于撤销静音。该变化不会使客户端支持模型目录热更新，也不会更改账号、模型目录或请求路由。

## Testing（验证）

覆盖首次提醒、普通关闭、跨挂载静音、混合状态保留守护进程、可探测的桌面进程、存储不可用，以及相同状态跨模式切换保持关闭、新状态再次出现。模型表单的现有目录与子代理回归一并验证。初次实现未连接官方浏览器扩展实例，后续在同一任务中通过已连接扩展补验真实组件渲染与静音交互；使用合成状态，不操作真实进程。

本轮以 6a13232d（基线提交）为基础检查未提交改动：相关前端回归 56 项通过，类型检查、前端生产构建、改动源文件格式检查、文档检查和差异空白检查通过。临时恢复旧的关闭状态重置逻辑时，相同状态跨模式切换的回归用例失败；恢复候选实现后通过。后端未改动，没有执行后端或完整桌面安装包验收。

后续继续以 62d23ade（当前基线提交）审查同一份未提交改动。模型表单恢复旧版操作的取舍另见[经典模型表单回退](2026-11-05-codex-classic-model-form.md)。

最终联合验证为 13 个测试文件、175 项通过；类型、格式、前端构建和文档检查通过。已在隔离浏览器页面验证“不再提示此类推测”后提示消失，重新加载仍不显示；已探测进程的保留由组件回归覆盖。
