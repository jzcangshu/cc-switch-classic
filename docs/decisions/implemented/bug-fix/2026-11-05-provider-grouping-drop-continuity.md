# Agent Note: 排序落位与卡片操作保持同一交互契约

Status: implemented（已实施）

## Problem（问题）

分组候选版在拖到位、停顿再松手时出现右偏和切换位置，保存期间还会短暂隐藏所有把手。菜单入口与悬停提示层组合错误导致点击无效；提供分组菜单的数据同时改变了整个操作区的显隐。关闭模式漏接第三版排序过渡，异步保存结束早于列表更新时回到旧顺序一帧。

## Decision（决定）

关闭与菜单模式共用普通排序卡片、传感器和位移过渡；菜单模式保留左侧把手作组内排序，归组通过菜单完成。只有拖拽模式启用悬停建组，卡片右侧分组入口仅在菜单模式存在，所有模式保留悬停或键盘聚焦才显示操作区的规则。菜单触发器直接包裹真实按钮，提示层放在触发器外，避免丢失事件与引用。

松手先同步发布最终顺序，再保存；收到实际顺序一致的列表数据才撤销临时顺序，保存失败明确回退。保存忙碌只禁用输入，不卸载把手。拖影抬升与落位共享一层变换和左上原点，尺寸比例只换算一次；测量节点保持静止，视觉布局动画移到内层。碰撞函数记录锚点与待执行效果，由传感器事件提交后执行，避免渲染期间更新另一组件。

## Alternatives considered（考虑过的方案）

1. **补固定横向偏移、延长显示延时**：只能掩盖某个卡宽或保存耗时，跨组缩进和长卡片仍会错位；因此修复坐标系与数据交接。
2. **菜单模式也使用悬停手势**：可共用更多渲染，但违背桌面操作的明确性；因此共用普通排序，只由菜单负责归属变化。
3. **保存时隐藏把手和全部按钮**：能阻止重复输入，但改变卡片几何并触发二次测量；因此保留结构，仅禁用相关操作。

## Consequences（收益与代价）

减少了拖影内部的缩放层与重复补偿，菜单和关闭模式没有额外动画状态机。代价是临时顺序必须与真实列表同步，失败路径必须显式释放；两种分组呈现仍共享业务提交与成员规则。组内排序保持普通上下交换，跨组归属在菜单模式通过菜单操作。

本决定调整[原分组模式决策](../feature/2026-11-04-provider-grouping-modes.md)中的常驻按钮和菜单不拖动约定，其数据共用与关闭保留分组的决定继续有效。模块规则统一维护在[分组契约](../../../development/provider-grouping.md)。

## Testing（验证）

回归覆盖菜单真实点击、三模式入口、把手保留、保存回调先于列表更新、排序失败回退、拖影尺寸及完成取消。内置浏览器使用生产组件、合成数据和仓库外记录器，按真实指针分步输入，覆盖到位停顿后松手及跨组缩进。记录显示修复前落位中向右偏移，修复后同组横坐标固定、把手全程存在、普通排序不回闪旧顺序。截图和逐帧数据保留在仓库外；桌面最终手感仍由维护者验收。
