# Agent Note: 供应商分组共享数据，分别提供拖拽与菜单交互

Status: implemented（已实施）

## Problem（问题）

候选分组功能依靠悬停与拖动完成归组，桌面用户缺少明确入口；没有分组时也无法创建第一组。折叠缩略图的负间距叠加文字回退溢出，遮挡相邻内容。落位计时与建组升格计时分别推进，会在拖影尚未结束时改变落点。

## Decision（决定）

在常规设置中设置“关闭 / 拖拽 / 菜单”。首次使用保持关闭；已有旧试用分组且未显式选择模式时沿用拖拽。关闭保留成员、顺序与折叠偏好。菜单模式通过常驻分组按钮创建、移动和上下排序，分组头负责改名、折叠、排序与解散。两种视图共用布局计算、操作计划与保存路径，主分区以外的账号、候选和队列按既有业务处理。

分组命令按应用更新一个桶，全量设置保存保护当前分组；乐观布局保存失败时重新读取真实状态。成员暂时不在主分区时保留归属，仅清理已删除标识。两步保存中若分组成功而排序失败，分别报告并重新读取，不能把部分成功包装为整体成功。

缩略图使用独立固定格和内容裁切。拖影与源卡片在动画完成或取消事件交接，计时器仅作异常兜底；新组等落位结束后才升入分组区。移动门槛按稳定停留起点累计，取消恢复因悬停展开的组。旧拖影的完成回调按拖动轮次隔离，键盘排序不启动悬停建组；保存中的成员操作暂时禁用，避免后一次提交被丢弃。运动参数和动画完成协议集中维护，减少动态效果时不让不可见源卡等待动画。

## Alternatives considered（考虑过的方案）

1. **只补拖拽的菜单兜底**：复用成本低，但桌面用户仍会被悬停建组干扰，且无法单独关闭；因此提供独立的菜单视图。
2. **两套分组存储及操作实现**：各模式可独立优化，但切换模式需要迁移成员并产生两个真值；因此只分离交互和渲染，复用数据与提交。
3. **继续依赖固定计时完成动画交接**：实现直接，但改一段时长就会改变另一段的正确性，浏览器取消动画时还可能挂起；因此正常路径以完成事件驱动，异常定时兜底保留。

## Consequences（收益与代价）

桌面用户可以通过按钮完成等价操作，模式切换不会丢失分组；动画状态不再依赖两个互相猜测的延迟。代价是需要维护两种呈现，并继续承担分组设置与排序接口分开提交的部分失败边界。拖拽的碰撞、建组预览和共享布局仍较复杂，本次仅提取运动协议及公共提交，不整体改写手势状态机。

现有决策目录没有重叠分组决策；详细规则唯一归属为[分组契约](../../../development/provider-grouping.md)，本文记录选择理由。后续若增加跨窗口同时编辑或更多布局方向，应重新评估原子分组排序接口和手势状态机。

## Testing（验证）

纯布局和菜单测试覆盖首次建组、移入移出、排序、解散、重复标识及暂时隐藏成员；持久化测试覆盖按应用保存、失败回退、排序部分失败、重复提交阻止和折叠恢复。手势测试覆盖慢速移动、离开目标、取消展开、落位完成交接、连续拖动回调隔离、键盘排序和减少动态效果；动画测试验证完成与取消都释放真卡。后端测试验证旧设置、三模式序列化和全量设置保护分组。实际浏览器验证生产列表、常规设置、长名称和不同窗口宽度；最终手感由维护者使用本地测试包验收。跨平台原生交互不以浏览器模拟替代。

全量回归暴露应用集成首个用例的动态模块导入与交互共用超时，超时后遗留异步渲染又干扰后续用例。集成夹具改为收集阶段静态加载应用，保留所有断言和原超时；拒绝通过扩大时间预算掩盖问题。原始失败、整文件复验及最终持续集成结果保存在仓库外的任务记录中。
