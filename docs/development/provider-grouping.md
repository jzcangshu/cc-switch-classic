# 供应商分组与拖动契约

涉及含供应商分组能力的候选版本时读取。产品外观见 [裁决手册](../maintenance/upstream-triage.md)，测试隔离见 [开发与验证](../maintenance/development.md)。悬停时长、边缘比例和动画参数以被审查提交的集中常量为准，修改参数须重新验证手感。

## 模式与桌面操作

常规设置的“供应商分组”采用“关闭 / 拖拽 / 菜单”三档。首次使用默认关闭；旧试用数据已有分组且没有显式模式时沿用拖拽。关闭仅改为平铺，恢复启用时沿用成员与折叠态；搜索也采用平铺，不改写成员。

菜单模式在卡片上提供常驻分组按钮，用于首次建组、移入、移出、上移和下移；组头提供改名、折叠、顺序调整和解散。解散只移出成员。两种模式共用布局与提交规则，菜单主区不注册拖拽操作，非主分区仍使用所属业务的排序。选择“菜单”是为了直接说明入口，而非含义模糊的“点击”。设计理由见[模式决策](../decisions/implemented/feature/2026-11-04-provider-grouping-modes.md)。

## 数据与适用范围

- 分组定义按应用保存于设置中的 providerGroups（供应商分组）字段；持久化命令在设置锁内只读改写当前应用的桶；全量设置保存保留最新分组。折叠态属于本地界面偏好，不增加数据库迁移或另一套供应商实体。
- 分组仅管理适用的主供应商区域。特殊账号、其他分区、故障转移队列按所属业务处理，不得因共用拖动上下文混入分组。
- 搜索时使用平铺结果；退出搜索恢复分组和折叠偏好。没有分组时不显示多余的“未分组”标题或管理框。
- 一个供应商在同一应用至多属于一个分组。删除供应商、移动最后一项、清理失效标识时维护成员关系；空组在确认提交后清理。
- 按最终分组顺序和成员顺序统一生成 sortIndex（排序索引），同步现有排序接口、故障转移缓存和托盘消费者，不能只改眼前的数组。
- 分组名、图标和计数采用同一紧凑层级。改名、折叠、分组排序及菜单移动是完整能力；菜单提供键盘和触屏可达路径。

## 拖动状态与持久化

拖动开始保存布局和分组定义快照。拖动中的 pending（待提交布局）与临时组仅用于预览，候选意图确认后才修改布局；按最终实际变化提交一次，取消时恢复完整快照。

| 状态/动作     | 必须保持的条件                                                             |
| ------------- | -------------------------------------------------------------------------- |
| 开始拖动      | 记录源容器、成员顺序、分组定义与测量尺寸；拖影独立于被重挂的业务节点       |
| 跨容器预览    | 容器和成员在同一更新中变化，防止重复项、空白中间态或先删除后插入闪烁       |
| 确认插入/建组 | 更新真实预览布局；保存确认过的落点和变化标记                               |
| 松手          | 提交确认过且有实际变化的布局；碰撞结果短暂丢失不能单独推翻已确认的落点     |
| 取消          | 恢复成员、顺序、临时组与相关界面状态；清理计时器和悬停指引                 |
| 保存与刷新    | 乐观状态和服务器回读衔接，不让旧对象覆盖新布局；失败保持可解释的回退与重试 |
| 外部设置保存  | 单字段更新及本地引用保护不能覆盖其他设置；刷新不能制造二次落位             |

预览期间不得把每一帧写入磁盘。无变化不提交；组定义和排序两步保存发生部分失败时，应明确错误并验证后续刷新可以恢复一致状态。

## 悬停与意图判定

使用项目已有的 dnd-kit（拖动组件库）多容器能力与动画库；应用专用意图保持在分组模块，布局计划尽量用纯函数表达。

1. 快速掠过只跟随指针，其他卡片保持原位。悬停计时必须控制**全部让位路径**，包括拖动库默认排序投影；仅延迟数组更新仍会造成提前挤开。
2. 卡片中部表示建组意图，边缘表示插入意图；仅两个符合条件的未分组卡片可建组。中部建组计时期间不能同时启动插入计时。
3. 折叠组使用独立展开意图；展开后重新计算目标。容器空白、卡片边缘和组内卡片要各有可解释的插入位置。
4. 意图连续且目标稳定才继续计时。目标变化或有效指针移动重置计时；确认让位后锁定意图，避免动画改变矩形又触发下一次让位或误建组。
5. 指针位置与活动卡片矩形职责不同；不要用宽拖影覆盖多个目标的面积代替用户当前指向。容器命中应收敛到有效成员，保留跨容器移动时的短暂碰撞连续性。
6. 无指针的键盘操作使用明确插入语义，建组通过等价菜单完成。不能把缺失坐标当作卡片中心。

## 视觉与落位连续性

- 拖影按原卡片的真实宽高固定测量，保留卡片内部密度。不能只复制外框，导致额度区、长地址和操作区在抬起时换行跳动。
- 拖动期间可见主体由拖影承担；源节点保留布局占位及可测量尺寸。跨容器重挂不能使本体闪现。
- 唯一建组指引是目标卡片四周的灰色认领板及适度缩放。插入以卡片实际让位表达，不添加蓝色光晕、插入光标或额外占位线。
- 建组容器出现和目标卡片进入同一节奏，不能先挤开再建组。离开目标时平滑撤回指引；临时组取消和空组收拢保持下方布局连续。
- 卡片位移、共享布局动画和拖动库投影不能争用同一层变换。落位期间保持最终布局，隐藏源节点的变换与最终目标矩形一致，避免松手后先弹回再跳到新位置。
- 拖影完成或取消后才交还真卡，再升入分组区；不能用相互独立的固定时长决定可见性与升格。缩略图使用独立格，文字回退与自定义图标不能越界。取消恢复悬停期间临时展开的组。
- 减少动画偏好下仍保留正确的状态、目标与可理解反馈。颜色、动效和动画时长不参与业务正确性判断。

## 验证清单

| 类别     | 需要覆盖                                                                                           |
| -------- | -------------------------------------------------------------------------------------------------- |
| 纯布局   | 同组前后插入、跨组移动、空容器、缺失目标、重复标识、快照不变、建组成员顺序、临时组解散、排序索引   |
| 状态时序 | 未到门槛不让位、中部不插入、意图切换重计时、确认后锁定、快速松手、取消清理、保存失败               |
| 集成     | 组内/组间排序、拖入/拖出、折叠后展开、改名、最后成员移出、搜索平铺、菜单等价操作、刷新及重启持久化 |
| 真实布局 | 宽窄窗口、长文本与额度、拖影尺寸、跨容器重挂、松手落位、外部刷新、减少动画                         |
| 手感     | 扫过不扰动、停留才让位、中心建组、连续拖动不蠕动、取消不闪现、灰色认领板无额外光晕                 |

自动化指针事件必须分步移动并保留实际时间轴；瞬时拖放不能证明悬停门槛和动画连续性。按任务约定由维护者进行手感验收时，交付具体场景与候选提交，保持“待手工验收”状态，不能由单元测试替代。测试替身的保存回调应返回真实更新后的设置对象，且提交前核对生产入口未包含本地替身脚本。
