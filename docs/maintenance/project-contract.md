# 项目契约

修改产品代码前阅读。产品范围与数据归属由本文定义；界面、功能筛查及逐项判断读取 [功能裁决手册](upstream-triage.md)，实施步骤读取 [上游同步](upstream-sync.md)。

## 产品与数据

- CC Switch Classic（经典版配置切换器）采用官方第四版内核，保留第三版 v3.20.4（视觉参照标签）的操作与外观。后端、协议、数据迁移、业务逻辑默认跟进上游；不能为复古界面删掉有效能力。
- 产品名称、反馈入口、下载和自动更新使用本项目身份。官方来源链接、许可证及历史发布说明可以保留上游署名；禁止的是把产品更新或支持入口误导到上游。
- 经典版版本与内核版本是两个独立维度；来源和修改清单见 [发布流程](release.md)，不得把读取应用内核版本的接口用于拼经典版发布链接。
- 语言仅保留 zh（简体中文）、zh-TW（繁体中文）、en（英文）、ja（日文）。旧的 tr（土耳其语）设置应回落英文，不恢复语言包、选项或类型分支。
- 不恢复赞助置顶预设、推广墙、推广追踪参数或相应排序字段；直营厂商的有效预设按产品用途保留。不用“仅保留登录类预设”的过滤方式裁剪其他应用配置；不要把某次扫描的供应商数量写成永久规则。
- 官方认证、第三方密钥、代理路由、原生配置和用户数据必须区分归属；切换模式不得覆盖不属于该模式的凭据或会话。

## 核心边界

- 第四版运行时、类型、命令、查询缓存和业务状态保持单一来源。第三版提供视觉参照，不建立两套业务状态或两套后端。
- 供应商编辑保留编辑投影、保存基线及冲突策略；用户查看某个模式不等于提交模式切换，聚合视图中的未来默认不标成当前实际默认。
- 设置页共享一个表单。目录字段显式保存；服务器刷新保留真实本地草稿，切页不丢输入；真正离开时执行未保存确认。存储迁移期间阻止背景保存旧路径。
- 扩展批量操作保留部分失败结果、失败重试与撤销，明确对全集还是筛选范围执行；不能把失败简化为成功布尔值。
- 会话保持结构化内容块和按需读取；正文、索引、恢复命令与用户目录属于同一数据边界，不能只为旧阅读器形态转回纯文本。
- 经典版自有功能应从现有扩展点接入。官方已提供等价实现时逐项核对行为与兼容性，复用其实现，保留本项目独特行为的最小差异。

## 明确拒绝的方案

| 方案                                   | 限制与理由                                                                           |
| -------------------------------------- | ------------------------------------------------------------------------------------ |
| 只保留账号登录类供应商预设             | 禁止。这会使部分原生配置类应用的预设列表为空；预设取舍按有效能力与推广边界判断       |
| 赞助置顶、爱心角标及推广追踪           | 禁止恢复；不得通过自动合并带回相应字段、排序、资源或专用测试                         |
| 土耳其语资源与分支                     | 不纳入产品语言集；旧设置回落英文，新增文本同步四语言                                 |
| 用量页整套第四版抽屉、指标条和级联筛选 | 保留经典版汇总卡、独立筛选与图表指标操作；新增数据与成功率、币种换算继续接入         |
| 用菜单替代常用账号操作                 | 重新登录、使用账号、删除等常用操作保持可见；菜单可保留次要新能力                     |
| 用第三版字段覆盖已演进的数据模型       | 禁止恢复已移除的通用配置片段、费用倍率或旧连通参数；新的同类功能须按当前接口独立判断 |
| 上游专用仓库设施                       | 赞助、所有者和发布配置不照搬；共用修复先检查本项目是否存在同一问题                   |
