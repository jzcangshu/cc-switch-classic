# 跟进官方内核

实施前读 [项目契约](project-contract.md) 和 [开发与验证](development.md)，实施后完整执行 [质量审查](review.md)。本流程不依赖某位维护者安装的全局工作流或助手技能。

## 1. 固定四个参照

记录官方仓库地址、本项目仓库地址和实际远端名；先获取远端引用，再确认目标正式版本。不能直接把移动中的主分支或“最新”两个字当审查对象。

- U0（上次已跟进的官方提交）：从现有内核版本及上次审查记录追溯到官方标签和完整提交编号。
- U1（本次目标官方提交）：本次确认要跟进的标签和完整提交编号。
- C0（本次经典版改动前提交）：真实起点，包含尚未发版的本地功能时也必须如实记录。
- C1（本次实现完成提交）：固定待审查对象；修复后更新此编号并重跑受影响检查。
- V3（第三版视觉参照）：v3.20.4（既定标签）及其提交编号。

确认工作区干净或明确分离他人改动。公共主分支与内核开发分支可能历史不同，不能通过提交时间或版本常量猜测包含关系。

## 2. 生成审查材料

在干净、已提交的候选分支上运行下面的命令。尖括号内容是需要替换的引用，不是可原样运行的参数；输出目录必须尚不存在。

```sh
pnpm review:prepare -- --upstream-base <U0> --upstream-target <U1> --classic-base <C0> --candidate <C1> --output <仓库外的新目录>
```

脚本只读取固定引用、生成差异清单和待填写的审查报告。它拒绝脏工作区、非当前候选提交、无效引用或不符合先后关系的基线；不修改代码、不调用模型、不运行产品测试，也不会生成“通过”的结论。

审查至少覆盖三组材料：官方变化 U0→U1、经典版实现 C0→C1、结果相对官方 U1→C1 的保留差异。最后一组可能包含长期差异，按领域区分既有契约和本次偏离，不能当作全部新增缺陷。

## 3. 建立覆盖清单再实施

按官方变更的文件和行为分类，不能只看合并冲突文件。文件无冲突也可能覆盖契约。每组记录来源提交、受影响领域、裁决、理由、实现位置与验证方式：

| 裁决                     | 含义                                                               |
| ------------------------ | ------------------------------------------------------------------ |
| adopt（直接跟进）        | 内核、协议、配置修复、事实修正及适用测试                           |
| adapt（适配）            | 保留能力，以经典版视觉和操作方式呈现                               |
| coreOnly（只取核心逻辑） | 拆出逻辑或数据变化，保留我方既有界面；不能整文件覆盖后跳过上游修复 |
| skip（不跟进）           | 纯上游皮肤、推广或不适用于本项目的仓库设施，说明理由               |
| verify（待裁决）         | 规则冲突、重大兼容或更新发布变化；解决之前不得视为已覆盖           |

实施顺序为：内核与配置 → 经典版差异消解 → 界面适配 → 四语言同步 → 依赖与构建核对 → 全面审查。依赖升级检查官方发布说明和锁文件变化，避免把无关大版本升级夹进同步。

## 4. 实现之后必须做的事

1. 将官方文件清单逐项映射到裁决记录。新增应用沿“类型与可见性 → 配置和认证 → 列表/空态/搜索 → 扩展/会话/用量 → 托盘和设置 → 四语言”追踪消费者。
2. 按质量审查文档进行行为、结构、安全、性能与真实界面检查；按项目契约的视觉区域表逐行回归。
3. 执行完整验证，闭环每项缺陷。未执行的原生或平台验证写清缺口，不用另一分支的旧检查结果替代。
4. 更新最终 C1（候选提交）及报告，把未解决阻塞项保持为待处理；验证通过后才进入 [推送步骤](release.md)。是否发版按任务授权单独决定。

## 可直接交给开发助手的任务提示

> 按本仓库统一入口进入“官方内核同步后审查”阶段。读取上游同步、质量审查、项目契约与开发验证文档，固定官方前后版本和经典版前后提交，生成审查材料并完成逐项覆盖。先形成有证据的问题清单，再在任务授权范围内修复和验证；检查真实布局、跨平台初始化、认证与配置隔离、版本更新口径和持续集成是否实际执行。不得把模板、测试替身或仅重跑通过当作完成。输出最终提交编号、裁决覆盖、缺陷闭环、实际命令结果和未覆盖项；没有明确发版授权时只交付代码。
