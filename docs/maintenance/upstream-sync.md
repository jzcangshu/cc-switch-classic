# 跟进官方内核

实施前读 [项目契约](project-contract.md)、[开发与验证](development.md)，固定参照后读 [功能筛查与适配裁决手册](upstream-triage.md)。实现完成后执行 [质量审查](review.md)。本流程可由一个贡献者完整执行，不依赖私人工作流、特定模型或子代理。

## 1. 固定参照与工作区

记录官方仓库、本项目仓库和实际远端名；获取远端引用并核实目标正式版本。移动中的主分支和“最新”不能代替固定提交。

- U0（上次已跟进的官方提交）：由现有内核版本和上次审查记录追溯官方标签与完整提交编号。
- U1（目标官方提交）：本次明确选择的官方标签与完整提交编号。
- C0（经典版改动前提交）：真实开发起点，包括尚未发布的本地能力。
- C1（实现完成候选）：固定待审查对象；修复后更新并复验受影响检查。
- V3（第三版视觉参照）：v3.20.4（既定标签）及完整提交编号。

确认工作区、分支和未提交改动。公共主分支、内核开发分支与发布分支可能历史不同，使用提交关系确认实际合并祖先；版本常量相同不代表代码相同，提交日期也不能证明包含关系。独立历史的集成必须明确内容基线和最终差异。

## 2. 生成范围与裁决材料

在干净且已提交的工作区运行：

```sh
pnpm review:prepare -- --upstream-base <U0> --upstream-target <U1> --classic-base <C0> --candidate <C1> --output <仓库外的新目录>
```

尖括号内容需替换；输出目录必须在仓库外且尚不存在。实施前可令 C0=C1=当前提交，生成官方变化和我方保留差异用于只读筛查；实施后使用新的输出目录，固定实际 C0/C1 并复用已核实的裁决编号。

工具输出固定提交、三组完整文件清单、裁决清单和未审查报告。它拒绝脏工作区、非当前候选、无效引用、倒置基线与复用输出目录。生成材料不修改产品代码、不执行模型裁决或产品测试，也不作出通过结论。

三组差异各有用途：U0→U1（官方新增变化）、C0→C1（本次实现）、U1→C1（最终保留差异）。最后一组区分长期契约和本次偏离，不能把全部既有差异当新问题。

## 3. 逐项筛查与覆盖对账

按 [裁决手册](upstream-triage.md) 的三条规则、五类裁决、区域标准及完整字段填写 [裁决模板](templates/upstream-triage.md)。先只读筛查，规则明确的条目直接进入实施；真正的规则取舍列入待确认。

- 从官方完整文件清单出发，逐项映射行为。无冲突合并、删除、重命名、测试和仓库设施都在范围内。
- 一项能力跨文件追踪调用链，一个文件有多个独立变化时拆条目；不得按每领域固定条数截断。
- 对待确认项写明冲突、建议、影响及解决条件；证据缺失列未覆盖，不能混作已采纳。
- 汇总五类数量与按路径去重的覆盖率，核对清单中的每条官方路径都被读取和裁决。共享组件、翻译和工作流单独交叉检查。

## 4. 合并与适配实施

建议顺序：内核与配置 → 我方差异消解 → 界面接线 → 四语言 → 依赖与构建 → 全面审查。每阶段更新裁决状态和实现位置。

### 三方合并与消费者

读取官方基线、官方目标和我方代码，按逻辑块消解。coreOnly（只取核心逻辑）要求保留上游状态、参数、回调和数据修复，同时维持经典版形态；整文件取任一方都会漏掉另一方的有效变化。

官方删除属性、改命令签名、修改类型或缓存键时，查所有消费者和源码断言测试。事件处理参数应使用真实事件契约，不能用忽略参数、宽泛类型或类型断言隐藏不兼容。官方已有等价能力时按输入、输出、失败、并发、旧配置逐项对照，复用其实现并保留经典版独特行为。

自动合并成功仍须检查 skip（不跟进）内容：推广预设和排序、赞助资源、土耳其语、上游专用文档、所有者配置、发布工作流及这些内容的专用测试。拒绝功能与其依赖一起核对，不能只移除可见入口。

### 四语言合并

只维护简中、繁中、英文、日文。逐键比较官方前后与我方：官方未改的保留我方有效译文，官方新增的补齐四语言，双方都改的按当前行为和第三版实际文案裁决。比较渲染文意，不只比较键名。

结构化资源合并需要以下守卫：

1. 修改前后记录每种语言的叶子数量与完整路径集合，逐项解释新增和删除。数量相同不能证明集合相同。
2. 写嵌套路径时只创建缺失节点，不能重建已有中间节点并清空整棵子树；四语言的共同缺失也须与代码引用和官方新增键对账。
3. 删除键先查引用、动态前缀及兼容回退，调整消费者后再清理。解析资源时检查重复键，普通 JSON 解析的后值覆盖不能用作重复键检测。
4. 检查插值变量、复数规则、格式占位和实际界面。默认回退中文不能替代其他三种语言。
5. 旧语言设置回落行为按项目契约验证，不恢复被排除的语言资源或类型分支。

### 依赖与持续集成

锁文件与依赖清单一起审查，核对升级理由、兼容范围和构建影响。查看工作流的每个作业：触发条件、路径过滤、历史深度、依赖关系、运行时、缓存和产物来源。打包作业使用缓存不代表安装步骤可省；缓存未命中时也必须具备完整构建前提。不要从一个绿色汇总状态推断测试实际执行。

## 5. 新能力与新应用接入核对表

每行写“实现位置与验证”或“有依据的不适用”。仅有后端或单页能显示不能算接入完成。涉及专门模块时按 [模块目录](../development/README.md) 读取字段和原生契约。

| 领域             | 核对内容                                                                                    |
| ---------------- | ------------------------------------------------------------------------------------------- |
| 应用身份与显隐   | 前后端应用类型、图标、名称、设置默认值、隐藏后的各页面消费者、深链接应用标识                |
| 配置与迁移       | 默认/覆盖目录、旧配置导入、未知字段、精确标识、缺失与损坏区别、原子写入、冲突和失败恢复     |
| 认证与切换       | 官方账号、第三方密钥、原生登录及代理归属；查看模式和实际提交分开；切换不破坏其他模式凭据    |
| 添加与编辑       | 预设、自定义、字段默认、模型来源、请求地址、协议、结构化与原始配置往返、保存失败保留输入    |
| 调用链           | 命令注册、接口封装、参数与返回类型、错误映射、事件签名、查询键及缓存失效                    |
| 列表             | 过滤、排序、特殊账号、分组、计数、空态、搜索真实地址、启用与移除语义                        |
| 提示词/协议/技能 | 支持范围、原生路径、应用开关、共享资源归属、批量部分失败、撤销和外部修改                    |
| 会话             | 真实原生布局、扫描/读取/恢复/删除能力、结构化内容、路径与会话标识校验                       |
| 用量             | 真实日志语义、去重与重写、缓存/思考是否重复累计、价格与币种、历史模型归属、图表真实尺寸     |

| 四语言与验收     | 完整键集和插值、真实文案、窄屏/触屏/键盘、负面路径、模块回归与当前提交证据                  |

## 6. 实现后的独立审查

先审正确性与接入质量，再审经典版界面一致性；同一人可以依次完成，但两种结果都要留下证据。对照 [质量审查](review.md) 全部章节和 [区域回归表](upstream-triage.md#5-第三版设计语言与区域回归表)，不是只看发生冲突的页面。

每个裁决条目补实现和验证结果，检查拒绝项残留，列出待确认与未覆盖。缺陷按“证据 → 修复 → 复验”闭环；修复后固定最终 C1（候选提交）。验证通过并处理缺口后进入 [推送步骤](release.md)，创建版本标签和安装包发布按任务授权执行。

## 可直接交给开发助手的提示

> 按统一入口进入官方内核同步阶段，固定官方前后、经典版前后提交及第三版视觉参照。先用裁决手册只读筛查全部变化，生成完整五类清单与覆盖对账；每项明确状态、事件、配置和具体接入做法。规则明确的条目继续实施，真正取舍列待确认。完成后分别审查正确性/接入质量与界面一致性，执行质量指引并闭环缺陷。输出最终提交、完整覆盖、实际验证及平台缺口，不把模板、测试替身或重跑通过当完成；发版按任务授权执行。
