# 上游功能筛查与经典版适配裁决手册

本手册用于逐项判断“是否接入、如何接入、如何融入经典版”。跟进官方内核时，在 [上游同步流程](upstream-sync.md) 固定参照后完整阅读；修改单个界面时阅读对应判例与区域标准。产品范围见 [项目契约](project-contract.md)，实现完成后的独立检查见 [质量审查](review.md)。

## 1. 裁决对象与证据

分别读取 U0（上次跟进的官方提交）、U1（目标官方提交）、C0（我方改动前提交）与 V3（第三版视觉参照）。按固定引用读取，不能把另一分支的工作区文件当作参照；路径不存在时先查该提交的文件树，确认是迁移、删除还是新增。

每个更新点先回答：官方修复了什么实际行为；我方同处是否已改动；第三版是否有可复用形态；变化涉及数据、接口、交互还是纯外观。一个文件内有多个独立行为时分别裁决；一个能力跨多个文件时用同一编号关联全部路径。

证据至少包括官方差异、我方实现和相关调用方。提交说明用于理解意图，结论必须落到实际代码；查不到写入未覆盖清单，不能凭功能名称补结论。

## 2. 三条裁决规则与成本标准

只有以下三项全部满足，才把界面恢复或适配为第三版形态；任一不满足时保留第四版能力并说明原因。

1. **范围**：只考虑易改或中等成本。第三版无对应物时，只裁剪多余按钮、徽章、菜单等纯界面附加物；带数据、带行为的新增能力保留。
2. **红线**：不得引入大量逻辑重构、事实误导、遮挡、溢出、盲滚、触屏不可用或丢失防误操作保护。
3. **动机**：针对旧用户明显陌生的按钮样式与颜色、徽章、品牌、页面命名和多余入口；纯行为优化、默认值优化及信息增减默认跟进。

| 成本/对应关系  | 如何识别                                                           | 处理方法                                                   |
| -------------- | ------------------------------------------------------------------ | ---------------------------------------------------------- |
| 易改           | 同一状态和动作，只调整现有样式、文案、图标、入口位置               | 对照第三版实现，检查共享消费者后适配                       |
| 中等           | 需要重组页面或组合已有组件，但业务状态、命令契约和数据流可直接保留 | 写出组件映射、事件接线及验证，满足三条规则才适配           |
| 高成本         | 要重建状态模型、移除有效字段、改变事务或牺牲功能才能形似第三版     | 保留上游结构；存在产品冲突时列待裁决                       |
| 第三版无对应物 | 新应用、新账号能力、新原生资源或全新业务操作                       | 能力保留，以现有家族组件接入；无价值的纯视觉附加项才可拒绝 |

无对应物不是“高成本”的同义词，也不是删除新功能的理由。额度默认显示“已用”是明确产品要求，显示设置仍保留。

## 3. 五类裁决及完成条件

| 裁决                     | 何时使用                                                                 | 实施必须交代                                                                     |
| ------------------------ | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------- |
| adopt（直接跟进）        | 内核、协议、配置、安全、事实修复与适用测试，且没有经典版契约冲突         | 行为、接口、依赖和测试如何进入我方链路                                           |
| adapt（适配后跟进）      | 新能力需要界面，或现有经典版区域新增交互                                 | 保留的能力、采用的第三版形态、组件与动作接线、四语言与验收                       |
| coreOnly（只取核心逻辑） | 上游同时更改了业务逻辑和已有经典版区域的第四版外观                       | 逐块指出采纳的状态/回调/参数与保留的外观，补齐关联消费者；禁止整文件覆盖遗漏修复 |
| skip（不跟进）           | 纯第四版皮肤、推广和明确不适用的仓库专用配置                             | 拒绝理由、依赖是否一起处理、自动合并后的残留检查                                 |
| verify（待确认）         | 产品规则冲突、证据不足、重大兼容取舍；更新、签名、版本比较及发布链路变化 | 冲突双方、可选方案、建议与需要决定的具体问题；未解决前不能计为已接入             |

同一提交可以同时包含多类裁决。后端改动默认直接跟进，但若更改命令名、返回结构或设置字段，应同时安排前端接线，不能以“后端自动合并成功”结束。

## 4. 已确立的判断标准

1. **入口与能力分开判断**：供应商搜索保留，以第三版浮动面板呈现。支持 Ctrl/⌘+F（查找快捷键），打开后聚焦，Esc（退出键）关闭清空，切换应用收起；搜索范围包含实际请求地址。
2. **管理块优先内嵌**：安装升级位于设置的关于页内；数据来源和环境检查用页内卡片组织，不随上游改成独立页或附加抽屉。原生资源的键名编辑等结构性需求按第 6 条处理。
3. **防误操作保护保留**：未保存确认、删除确认和撤销、禁用原因、搜索时限制收起、直连格式提醒、目录草稿保护都属于行为契约。
4. **状态语义保留**：查看模式与实际模式分离；结构化会话、扩展批量操作和部分失败结果继续使用当前业务模型。
5. **事实准确性优先**：安装清单、新应用名称、空态与模型能力必须真实。先还原翻译键对应的文字再与第三版对照，不机械复制失实旧文案。
6. **结构冲突保留能力**：提示词内页头、按原生键名工作的协议编辑抽屉、结构化会话阅读器可以保留上游结构；记录无法恢复第三版形态的具体原因。
7. **说明随结构**：恢复页面手风琴或小节时，同时保留该结构中的常驻说明；单个字段的小字或帮助提示不做全局反向恢复。
8. **默认行为和底层可用性**：保留返回目标、配置档显隐等上游优化，以及滚动条、自绘输入、浮层动画、主题切换、字体和键盘焦点修复。
9. **形态与数据混合适配**：玻璃汇总卡继续展示新增成功率、币种换算；关于页保留近期更新和便携提示；新套餐、重置次数、余额和明细不能为横排额度样式而丢弃。
10. **失败态清晰且紧凑**：卡片显示带图标、固定“查询失败”文字和刷新动作的胶囊；完整错误进入悬停或展开区域，不塞进额度列。未配置账号与后端明确报错分开；有成功缓存时也不能吞掉本次业务失败。
11. **常用动作直接可达**：设为默认、账号重新登录/使用/删除、模板编辑/删除沿用常驻入口。卡片悬停操作在触屏和窄屏直接显示；菜单承载次要新能力。
12. **四语言同批落地**：第三版已有且事实准确的文案沿用对应语言原文；新增键同步简体中文、繁体中文、英文、日文，检查实际显示，不能靠中文默认值掩盖漏译。

## 5. 第三版设计语言与区域回归表

每次内核同步按表逐行记录结果；单项改动至少检查其所在行与共享组件。样式值以参照源码和本项目设计令牌为准，必要的可用性修复仍要保留。

| 区域             | 实施与验收标准                                                                                                                  |
| ---------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 窗口、页头       | 微软桌面系统原生标题栏；跨平台拖动、顶部缩放正常；品牌字动效指向本项目；独立用量和更新入口；不堆模式徽章                        |
| 供应商主操作     | 橙色圆形添加钮及悬停提示；加入按钮蓝底；使用中主色实底禁用；启用浅底；保持准确动作文案                                          |
| 卡片操作         | 悬停整组操作；窄屏与触屏直接显示；健康圆点、共存配置高亮；不恢复官方徽章、整卡变淡或旧队列上下移按钮                            |
| 搜索、空态、分组 | 浮动搜索面板可聚焦、可清空；普通卡与特殊账号卡共同参与空态判断；自有分组按 [分组契约](../development/provider-grouping.md) 检查 |
| 额度与查询失败   | 横排周期徽章、常驻更新时间/刷新、彩色进度条；默认已用，保留显示设置；多套餐默认展开；失败态按第 4 节执行                        |
| 认证中心         | 标题、简介和组副标题一致；账号常用动作可见；额度列在临界宽度不压缩名称、不溢出；新卡片沿用兄弟卡片字号、背景和圆角              |
| 协议与技能       | 独立应用数量条、全宽搜索、行内彩色开关；数量针对全集；批量操作默认折叠并说明筛选范围、失败重试和撤销；自定义胶囊与按钮文案一致  |
| 提示词、模板     | 总数/启用状态、独立卡片、直接编辑删除和共同保存；跨应用复制可放更多菜单；原生系统文件与模板不冒充启用中的提示库项               |
| 设置、目录       | 六页签共用表单；选中页签蓝底白字胶囊；语言/主题/存储/同步采用横排按钮组；目录紧凑单列、显式保存；小节内必要说明常驻             |
| 路由、数据来源   | 路由手风琴；数据来源页内三卡、模型元数据整卡；模式查看不触发实际切换；准确显示默认与实际生效状态                                |
| 关于、应用管理   | 第三版关于页；环境检查及安装升级内嵌；应用卡片网格、环境徽章、已安装分组和拖动把手；不重复安排功能入口                          |
| 会话             | 恢复命令预览、常驻删除及批量结果；左栏刷新、批量管理、收起；搜索自动展开时明确限制收起；结构化内容和分块读取保留                |
| 用量             | 玻璃汇总卡、品牌图标、短数徽章、成功率；两个独立下拉、图表自带指标切换；明细数量完整显示；显示项和列选择位于设置                |
| 弹窗与公共组件   | 压暗毛玻璃遮罩，标题/底条浅灰条带与分隔线；标题沿用第三版字号；二级页使用全称；长文字、焦点、滚动、暗色主题和减少动画正常       |

## 6. 按领域组织筛查

| 领域           | 优先检查的代码面                   | 必须横向追踪                             |
| -------------- | ---------------------------------- | ---------------------------------------- |
| 主布局与导航   | 主应用、应用切换、配置档、导航逻辑 | 显隐设置、模式查看/提交、窗口平台行为    |
| 供应商与额度   | 列表、卡片、呈现模型、各额度底栏   | 过滤、空态、缓存、分组和账号特殊分支     |
| 添加与编辑     | 各应用表单、添加/编辑对话框        | 编辑投影、保存基线、认证归属、原生往返   |
| 设置与认证     | 设置、账号组、应用管理、技能存储   | 单字段保存、迁移保护、全量自动保存影响   |
| 提示词         | 提示库、系统文件、原生模板         | 文件内容匹配、外部修改、备份及启用语义   |
| 协议与技能     | 扩展页面、通用应用开关、批量操作   | 目录归属、传输能力、部分失败与撤销       |
| 会话           | 发现、读取、内容引用、恢复和删除   | 真实原生布局、路径校验、索引一致性       |
| 用量           | 仪表盘、趋势图、日志、导入器、价格 | 几何尺寸、去重游标、缓存口径与历史归属   |
| 公共视觉与托盘 | 样式令牌、基础组件、主题、托盘面板 | 所有消费者、平台初始化、键盘与触屏       |
| 前端逻辑和资源 | 查询钩子、接口、类型、配置、翻译   | 命令签名、字段默认、完整键集和兼容       |
| 后端与持久化   | 服务、配置、代理、数据库           | 旧数据、认证、事务、未知字段、更新链路   |
| 仓库与交付     | 工作流、依赖、脚本、文档、推广资源 | 本项目身份、签名、权限、自动合并的拒绝项 |

每条路径都必须有归属。领域内按行为列条目；没有用户可见变化的文件仍需记录其依赖、测试或机械调整用途。大范围变化分批续查，不用每领域固定条数上限截断结果。

## 7. 裁决记录格式与自动化要求

使用 [裁决清单模板](templates/upstream-triage.md)。每条至少有：编号、领域、变更层、标题、完整文件集合、官方证据、我方与第三版对照、成本判断、裁决、具体接入做法、冲突化解、测试和完成状态。层级可取 backend（后端）、ui（界面）、i18n（翻译）、config（配置）、docs（文档）、tests（测试）。

汇总五类数量、覆盖路径总数与未覆盖列表。一个路径多个条目允许重复计入条目数，覆盖统计应按路径去重；重命名包含源和目标，删除包含消费者处理。待确认、未读取和未映射都保持显式状态，不能计作采纳。

开发助手执行要求：

- 先加载本手册与项目契约全文，缺失即报告缺口，不使用内置旧快照作替代。
- 固定四个参照后只读筛查；每个条目使用真实代码证据，做法必须落到组件、状态、事件或配置边界，不写“按经典版适配”一句结束。
- 输出五类分组清单及覆盖对账。由维护者处理真正需要取舍的待确认项，规则明确的条目直接继续。
- 运行方式可以是主会话顺序处理或已获授权的分工；分工时写集合互不重叠，共享翻译和基础组件集中整合，不依赖特定供应商或模型。
- 中断时保留已核实条目与未完成列表。候选代码或规则变化后重新验证受影响条目，不能盲用上一轮结论。

完整提示：

> 按当前裁决手册，对固定的官方前后提交和我方提交逐项只读筛查，第三版标签用于视觉对照。覆盖所有变化文件与行为，按领域给出五类裁决；每项写明真实证据、成本、采用的具体形态、接入位置、冲突处理及验证。禁止遗漏无冲突合并文件，禁止截断条目数，无法读取或决定的内容分别进入未覆盖和待确认清单。对账完整后按上游同步流程实施。
